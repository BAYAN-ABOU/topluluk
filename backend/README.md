# دليل الجالية — Backend

API حقيقي متصل بقاعدة بيانات PostgreSQL، بيحل محل الـ localStorage يلي كان مستخدم بالنموذج الأولي.

## طريقة التشغيل (على جهازك المحلي)

### 1. تثبيت المتطلبات
- Node.js (نسخة 18 أو أحدث)
- PostgreSQL (نسخة 14 أو أحدث) — منصوح تنزليه من postgresql.org أو تستخدمي Docker

### 2. إنشاء قاعدة البيانات
```bash
createdb community_directory
psql -d community_directory -f db/schema.sql
```

### 3. إعداد متغيرات البيئة
```bash
cp .env.example .env
# عدّلي القيم حسب بيانات الاتصال عندك (مستخدم/باسورد بوستغرس)
```

### 4. تثبيت الحزم وتشغيل السيرفر
```bash
npm install
npm run dev
```
السيرفر رح يشتغل على: `http://localhost:4000`

## اختبار الـ API

**جلب كل البروفايلات:**
```
GET http://localhost:4000/api/profiles
```

**فلترة (أطباء بإسطنبول):**
```
GET http://localhost:4000/api/profiles?service=doctors&city=إسطنبول
```

**إضافة بروفايل جديد:**
```
POST http://localhost:4000/api/profiles
Content-Type: application/json

{
  "full_name": "د. سامر الحلبي",
  "headline": "طبيب أطفال",
  "service_slug": "doctors",
  "city_name": "إسطنبول",
  "area_name": "الفاتح",
  "languages": "عربي، تركي",
  "bio": "استشاري أطفال...",
  "details": { "specialty": "أطفال", "years_experience": 12 }
}
```

## الخطوة الجاية المنطقية

1. **ربط الواجهة الأمامية (الـ HTML يلي بنيناه) بهاد الـ API** بدل البيانات الوهمية — استبدال `fetch` مكان الـ localStorage
2. **نظام تسجيل دخول (Authentication)** حتى صاحب البروفايل يقدر يعدّل بياناته لاحقاً
3. **رفع الوثائق للتوثيق** (حالياً الجدول `verification_documents` موجود بس لسا ما في رفع ملفات فعلي — بيحتاج تخزين متل AWS S3 أو Cloudinary)
4. **نشر السيرفر** على استضافة حقيقية (Railway, Render, أو Fly.io كلهم عندهم خطط مجانية للبداية)

## ليش هيك بنيتها (قرارات مهمة)

- **حقل `details` (JSONB)**: بيسمح لكل نوع خدمة يكون إله بيانات خاصة (دكتور عنده تخصص، مكتب عقاري عنده نوع الصفقة) بدون ما نغيّر بنية الجدول كل مرة نضيف خدمة جديدة
- **جدول `verification_status`**: كل بروفايل جديد بيدخل "pending" افتراضياً — ما حدا بيظهر كـ"موثّق" تلقائياً، لازم مراجعة يدوية (هاد مهم جداً لمصداقية التطبيق)
- **فهارس البحث (indexes)**: مبنية من البداية على الخدمة والمدينة والمنطقة، لأنو هاي أكتر شي المستخدم رح يفلتر فيه
